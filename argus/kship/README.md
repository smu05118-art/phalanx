# 한국조선 (KSHIP) — ARGUS 하위 대시보드

국내 상장 **조선사·조선기자재사**의 수주를 산업 특성대로 읽는다. 건설 탭(`argus/kce`)의 DART 수집·파서를
그대로 재사용하고, 조선에만 있는 축을 새로 만들었다.

진입: [`argus/index.html`](../index.html) 헤더의 **⚓ 한국조선** → [`index.html`](index.html)
인수인계·실행 순서: [HANDOFF.md](HANDOFF.md)

## 축 — 무엇을 어디서 읽는가

| 축 | 원천 | 화면 |
|---|---|---|
| 수주잔고·신규·기납품(매출인식) | 정기보고서 II-4 **부문 롤포워드**(원화) | 조선사 페이지 롤포워드 표·누적 막대 |
| **선종·척수·인도시점·상대·지역·대금조건** | 수시공시 「단일판매ㆍ공급계약체결」(척당) | 선종 구성 · **선표**(계약기간 종료일→분기) · 계약 표 |
| 환노출·**환헤지** | II-5 위험관리 · 주석 「파생금융상품」(통화선도 명목액·평균만기) | 환율·환헤지 카드 — 비율은 회사가 공시한 약정환율이 있을 때만 |
| **반복건조(시리즈)** | 공시에 없음 — 같은 선종·상대·지역, 수주일 180일 이내를 묶은 **추정** | '추정' 표시 |
| 기자재 **부품 분류**(대분류 14·소분류 54) | 정기보고서 II-2 주요제품 + KIND 문구 → 키워드 규칙 | 기자재사 페이지 · 인포그래픽 |
| 기자재→조선사 **연결** | 정기보고서 II 절 본문의 조선사 언급(횟수), 비중은 적힌 경우만 | 근거 등급(주요고객 주석 > 계약 공시 > 본문 언급 > KIND) |

모집단은 네 겹이다 — ① KIND 업종(선박 건조) · ② KIND 제품 문구의 해상 어휘 · ③ 사유를 적은 지정 · ④ **정기보고서 본문 탐색**(`tools/kship_scan.py`: 기자재 어휘에 걸리는 상장사 ~230곳의 사업의 내용에서 조선 낱말 횟수·조선사 언급을 세어 기준을 넘는 회사만 승격, 제외도 근거와 함께 커버리지 페이지에 남김. 주 1회 `scan-kship.yml`). 승격은 다음 스캔으로 **이월**되고 강등은 본문을 성공적으로 읽고도 기준 미달일 때만이다 — 9/12 스캔이 승격 16사를 지워 57→41 로 되돌아간 회귀를 9/30 복구(HANDOFF·MODEL.md §6-16).

정기보고서 수주표에 선종·척수가 **없다**는 것이 이 탭의 출발점이다(2026 반기 3사 실측). 그래서 척당 계약
공시를 원장으로 쓴다 — 계약상대는 81%가 '○○ 소재 선사'로 익명이며, 그 사실을 화면에 그대로 둔다.

## 실적 모델 (2026-09-30)

사용자 애널리스트 `subQ` 모델 3개(세진·삼성중·HD현대미포)를 레퍼런스로 57사 전부(+ 합병 소멸한 HD현대미포 = 모델 58)에 **분기 실적 모델**을 붙였다 — DART 재무제표를 FnGuide 계정명으로
정리한 `tools/assets/fin/`, ECB 환율 `fx.json`, aikstockdata 시세 `prices.json`(출처표기·비영리), 척당 계약 원장 기반 선표 `sls/`, 역할별(조선사·지주·엔진·기자재·강재)
모델 `models/<stock>.json` → 회사 페이지 하단 「실적 모델」 섹션 + 허브 [`models.html`](models.html) + 생성 xlsx `models/<stock>_model.xlsx`. 추정은 전부 `kind:estimate`+근거,
밸류에이션은 구간이며 목표주가·추천이 아니다. 2026-09-30 21:50 실측: 회사 페이지 57장 섹션 · 모델 58(full 29 · partial 29) · xlsx 58 · 골든 대조 91.1% · 테스트 245건 OK. 설계 계약 [MODEL_SPEC.md](MODEL_SPEC.md) · 실측·가정·한계·재현·2차 검증 기록 [MODEL.md](MODEL.md). DART 재무 수집은 프로세스 하나로만 돌린다.

**2026-10-02 갱신(MODEL.md §12)**: 남은 결정을 실행했다.
- 신규수주: 패널이 있는 조선사(삼성重·HD현대重·대한조선, 지주는 종속사 경유)는 forecast_panel base 신규수주를 매출에 포함하고, 보수/낙관은 시나리오로 따로 둔다. 한화오션·HJ 는 패널 값이 없어 잔고와 공시 수주만 담는다.
- 코호트: 수주연도 기준을 기본으로, 원장 내부 상대를 대안으로 둘 다 저장한다. 대한조선은 잔고 캡 0.8593.
- 재무 주석: 하위 노드가 없는 분기(999 중 786)는 부모 주석 절을 받아 읽는다. 이자수익이 51/58사에 채워졌고, 골든 대조는 5,378/5,900 = 91.2% 다.
- 고객 연동: 동결 백테스트(OOS)에서 추세보다 나쁘면 채택하지 않는다.
- 결함 수정: 적대 검토 결함 10건(신규수주 이중계산 · 음수 세율 5% 클립 · 코호트 경로 소멸 등)을 고쳤다.

현재 모델 58(full 48 · partial 10 — full 은 이제 '데이터 완전'만 뜻한다). 삼성重 FY2028E 매출 192,093억(모델 산출값). 자동 갱신 워크플로에 주석 수집 단계를 추가했다.

**2026-10-05 검증(MODEL.md §13)**: 위 수치는 산출 파일과 일치했다. 테스트 343 OK(skipped 24). 러너는 10-01·03·04 에 돌았지만 재무·주석 단계가 캐시 폴더 부재로 수집 전에 실패했었고(10-04 수정), 수정 뒤 첫 실행은 10-05 10:40 KST 다. 주간 스캔 워크플로는 openpyxl 미설치로 테스트가 실패해 9/26 뒤 커밋이 없었다 — 고쳤다. 재현은 `tools/run_all.sh`(아래).

**2026-10-05 전수 검증·통합(MODEL.md §14)**: 레인 10개가 소유 파일을 검증·수정하고 통합 레인이 전 파이프라인을 다시 돌렸다. fin 은 비용 부호 규약을 '양수'로 통일하고 주석 파서·차입금 라벨을 보강했으며(KCC 이자손익 부호·한화오션 총차입금 공백 해소, 골든 5,378/5,900 = 91.2% 불변), 시세 이력은 토스 대신 네이버 일봉(KRX 정규장)으로, 모델·xlsx 에는 조정EPS·BS 롤·시나리오 시트·영업외 세부 행 수식이 붙었다. 재생성 결과 모델 58(full 48 · partial 10) 그대로, 한화오션 FY2026E EPS 6,295.5 → 6,083.1원(이자비용 추정 복원). 테스트 **489 OK(skipped 2)**, 교차 정합 검사기 `tools/selfcheck_models.py` 486,140건 중 실패 19(지배주주순이익 파생 셀의 출처 표기 — 값은 일치, 미수정). 모델 산출값은 추천이 아니다.

## 정직성 규칙(건설 탭과 같다)

원문이 지지하는 것만 싣고, 추정은 `추정`·근거 등급으로 표시한다. 통화·단위는 표마다 읽어 정규화하며
(백만원·백만달러), 못 읽으면 `unit_seen=false`로 남긴다. 분류하지 못한 제품은 `tools/assets/unclassified.csv`에
쌓이고, 사람이 `parts_override.csv`로 지정하면 빌더가 반영한다.

## 갱신

`.github/workflows/update-kship.yml`이 매일 10:40 KST에 돈다(척당 계약 공시는 수시, 정기보고서는 분기; 실적 모델은 월요일·재무 변경·수동 입력 때만). `scan-kship.yml` 은 매주 일요일 02:00 KST 모집단 탐색.
DART는 동시 프로세스에 약하므로 수집기는 하나씩 돌린다.

로컬 재현은 `tools/run_all.sh` 한 줄 — 기본은 캐시·산출물만으로 도는 오프라인(선표 → 모델·xlsx → 페이지·허브 → 테스트 → 요약), 네트워크 단계는 `--collect`(KIND·DART) · `--fin` · `--notes` · `--market` 플래그로만, `--dry-run` 은 명령만 보여 준다. 분기 규칙·순서는 워크플로와 같다(`tests/test_run_all.py` 가 지킨다).

참고용 · 투자조언 아님.
