# ☢ 한국원전·발전기자재 (`argus/knuke`)

국내 상장 **원전·발전기자재** 기업의 수주를 이 산업의 축으로 읽는 ARGUS 탭이다.
체계업체(두산에너빌리티·한전기술·한전KPS)뿐 아니라 **부품·기자재사까지 전수**로 담는다 —
이름이 아니라 원문(KIND 업종·주요제품, 정기보고서 II절 본문) 근거로 넣는다.

## 이 탭을 읽는 법

- **허브**(`index.html`) — 회사 카드(수주잔고·잔고 커버리지·발주처 집중도·수출비중), 발전원별
  잔고 구성, **호기·사업 타임라인**(계약기간이 2030년대까지 뻗는 회사), 최근 대형 계약.
- **회사 페이지**(`<종목코드>/index.html`) — 수주잔고 추이·롤포워드, 정기보고서 수주 목록
  (발주처·사업명·계약기간·기본도급액·완성공사액·계약잔액), 호기 타임라인, 부문 매출,
  공급 계층 구성, 계약 상대, 계약 공시, 부품·납품 관계.
- **커버리지**(`coverage.html`) — 모집단 네 겹 전수와 편입 근거, ③ 본문 탐색 승격/제외,
  계약 진행(XI-1) 회사 × 반기 수집 상태.
- **계약 진행(XI-1)** — 반기·사업보고서 XI-1 「나. 단일판매ㆍ공급계약 진행 현황」에서 계약마다 판매ㆍ공급 누적·대금수령 누적을
  읽어, 계약 공시 표에 **'진행(XI-1)' 열**(막대 = 계약금액 100%: 수령·매출채권·선수금·잔여)을, 회사·허브에 `#xi1` 섹션을 붙인다.
  진행 = 판매ㆍ공급 누적 ÷ 계약금액(회사 자기 보고, 반기 스냅숏 — 회계 진행률 아님). '—' 는 0 이 아니라 진행 표에 없다는 뜻.
- **인포그래픽**(`parts.html`) — 원전·화력 단면에서 부품 영역을 눌러 그 기자재를 만드는 상장사로.

## 왜 수주기반인가 (원문에서 확인)

1. **발주처가 실명이다.** 한전기술 II-4 수주표는 발주처 칸이 전부 '한국수력원자력'이다
   (조선의 '○○ 소재 선사' 익명 문제가 없다).
2. **계약이 초장기다.** 신한울 3,4호기 종합설계 2016→2033, 요르단 IPP3 O&M 2013→2039.
   계약기간이 행마다 있어 **호기 타임라인**을 만들 수 있다.
3. **주기기와 정비가 다른 장사다.** 두산에너빌리티는 신규 착공에, 한전KPS는 가동 호기 수와
   계속운전에 붙는다 — 한 화면에서 갈라 본다.
4. **수출이 축이다.** 체코 두코바니·루마니아 CTRF. 국내 발주(한수원)와 해외 수주는 리드타임이 다르다.
   수출 계약은 **계약명이 영문**이라(`O Mon IV Thermal Power Plant`·`PP12 Expansion CCGT IPP`)
   분류 사전에 원문에서 본 영문 표기를 함께 넣었다.

## 재현

```sh
cd argus/knuke/tools
python3 build_dicts.py --write        # 발전원·공급계층·부품·SVG 사전
python3 knuke_scan.py --scan          # ③ 본문 탐색(정기보고서 II절)
python3 knuke_universe.py --write     # 네 겹 모집단
python3 knuke_contracts.py --collect && python3 knuke_contracts.py --build
python3 knuke_reports.py --collect --n 8 && python3 knuke_reports.py --build
python3 ../../kce/tools/xi1_sector.py knuke --collect --build   # 계약 진행(XI-1) — 로컬 확인은 --build --no-hdr 만
python3 knuke_suppliers.py --build
python3 knuke_page.py --all
python3 knuke_parts.py
python3 -m unittest discover -s tests
```

출처는 전부 DART 무키 경로(정기보고서·수시공시)와 KRX KIND 상장법인목록이다. API 키를 쓰지 않는다.
참고용이며 투자조언이 아니다.
