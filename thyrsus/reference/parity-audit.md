- **감사일**: 2026-08-31
- **대상 A (참조)**: teeroz 시계탑 — https://clocktower.teeroz.net/ko (Next.js App Router)
- **대상 B (감사 대상)**: `/home/user/phalanx/thyrsus/index.html` (단일 HTML, 3,836줄 / 305 KB)
- **방법**: teeroz는 직접 렌더링이 `ERR_CONNECTION_RESET`이라 curl로 HTML·JS·API 응답을 받아 로컬 미러(127.0.0.1:8091)로 재구성해 Chromium 렌더링. 게임 진행 모드는 `POST /api/games` → `GET /api/games/{id}` 를 로컬 스텁으로 대체해 **로그인 없이 실제 클라이언트 코드를 그대로 구동**했다. 티르소스는 127.0.0.1:8092로 서빙해 동일 조건(1440×1000 / 440×956, dark, ko-KR)에서 대조.
- **저작권 주의**: 본 문서는 화면 구조·요소 존재 여부·개수·순서만 기술한다. teeroz의 능력 설명 산문·가이드 문장은 복제하지 않는다.
- **감사 중 대상 변경**: 감사 진행 도중 다른 세션이 `index.html` 을 커밋했다(`cb180fa`, 312,518 → 314,045 B). 변경분(사망 처리 리팩터·좀버얼 2회 사망·보호 만료 타이밍·종료 조건 보강)을 확인해 영향받는 항목(B4)을 재검증·정정했다. 그 외 항목은 변경분과 무관함을 diff로 확인했다. 감사 기준 커밋은 `cb180fa` 이다.

### 로그인 관련 확인 사실

`/api/auth/session` 은 비로그인 시 `null` 을 반환한다. 그럼에도 **게임 설정(`/ko/game`)과 진행 화면(`/ko/game/{id}`)의 클라이언트 로직은 로그인 없이 전부 동작한다.** 로그인이 실제로 막는 것은 (a) 게임을 서버에 생성/저장(`POST /api/games`), (b) `내 게임` 목록·삭제, (c) `내 스크립트` 뿐이다. 즉 **진행 모드 자체는 로그인 벽 뒤에 있지 않고, 저장만 로그인에 묶여 있다.** 미러 스텁으로 이 저장 계층만 대체해 전 구간을 실측했다.

## B. 누락·불일치 상세 (우선순위 순)

우선순위 = 사회자 실사용 영향도 우선, 동률이면 재현 난이도 낮은 순. 항목 번호(B1…B18)는 참조 안정성을 위해 고정한다 — **실제 착수 순서는 D절 표를 따른다**(B4는 재조사 후 영향도가 상→중으로 내려가 D절에서 9위로 이동했다).

### B1. 밤 진행이 "단일 선형 위저드"가 아니다 — 단계 간 자동 연결 없음
1. **teeroz**: 밤 진행이 하나의 모달 위저드로 `1/9 → 9/9` 까지 끊기지 않고 이어진다. 각 단계에서 `다음`을 누르면 곧바로 다음 캐릭터 단계가 뜨고, 마지막이 새벽이다. 사회자는 모달을 한 번 열고 밤을 끝까지 진행한다.
2. **티르소스**: 밤 단계가 리스트로 나열되고, 각 항목의 `▶ 인터랙티브 진행`을 눌러 개별 모달을 연다. `✓ 완료`를 누르면 모달이 닫히고 다음 캐릭터로 이어지지 않는다. 12단계 밤이면 모달을 12번 열고 닫아야 한다.
3. **재현 난이도**: 중 — 위저드 큐(현재 밤 단계 배열)를 만들고 `완료` 시 다음 인덱스의 `startWiz`를 호출, 마지막에 새벽 씬을 붙이면 된다. 씬 엔진 자체는 이미 있다.
4. **영향도**: 상 — 실제 진행 중 가장 반복되는 조작이며, 어두운 방에서 리스트로 되돌아가 다음 항목을 찾는 것이 teeroz 대비 명확한 마찰이다.
- 참고: `tz-night-step1.png`, `tz-night-step2.png`, `tz-night-step3.png` ↔ `th-night1.png`, `th-night-wizard.png`

### B2. 새벽 사망자 자동 집계 화면 없음
1. **teeroz**: 밤 위저드 마지막 단계가 `아침이 밝았습니다` + 그 밤의 사망자 명단(좌석번호+이름)이다. 사망자가 없으면 그렇게 표기한다. 여기서 바로 `낮으로` 진행.
2. **티르소스**: 밤 리스트 하단에 정적 안내 문구(`🌅 새벽 — …`)만 있고, 그날 밤 판정 결과로 누가 죽었는지 집계해 보여주는 화면이 없다. 사회자가 그리모어/기록을 직접 확인해야 한다.
3. **재현 난이도**: 하 — 사망 판정(`doImpKill` 등)은 이미 기록에 남고 있으므로, 밤 시작 시각 이후 사망 이벤트를 필터링해 새벽 카드로 렌더하면 된다.
4. **영향도**: 상 — 새벽 공표는 사회자가 매 밤 반드시 하는 발화이고, 누락·오공표가 곧바로 게임 오류가 된다.
- 참고: `tz-dawn.png`, `tz-dawn-death.png` ↔ `th-night2-kill.png`

### B3. 밤 대상 선택 시 "기기 전달" 플레이어 대면 모드 없음
1. **teeroz**: 악마·독살범 등 대상 지정 능력에서 전체화면 야간 오버레이가 뜬다. 좌석 원형 순서로 플레이어 목록이 깔리고 본인은 `(나)` 로 표시되며, **플레이어가 직접 자기 대상을 탭**한 뒤 `이야기꾼에게 넘겨주기`로 기기를 돌려준다.
2. **티르소스**: `🫵 플레이어가 지목한 대상을 탭하세요` — 사회자가 플레이어의 손가락 지목을 보고 대신 입력한다. 플레이어가 기기를 잡는 흐름이 없다.
3. **재현 난이도**: 중 — 캐릭터 확인 릴레이의 전체화면 오버레이 패턴을 재사용하고, 좌석 기준 회전 정렬 + `(나)` 표기 + 복귀 버튼을 추가한다.
4. **영향도**: 상 — 온라인/조용한 진행에서 실질적 차별점이고, 사회자가 지목을 잘못 읽는 오류를 없앤다.
- 참고: `tz-night-target-picker.png`, `tz-night-handoff.png`

### B4. 종료 결과 화면과 `게임 종료` 버튼이 없다 (판정 자체는 있음)
> 정정: 초기 조사에서 `gameOver`/`checkWin` 명칭으로 grep해 "자동 감지 없음"으로 잘못 판단했다. 실제 함수명은 `checkEndConditions()` 이며 판정은 오히려 teeroz보다 촘촘하다(→ C-18 참조). 남는 격차는 **표현 계층**뿐이다.

1. **teeroz**: 종료 조건 충족 시 `winner`/`winReason` 을 담은 **결과 모달**이 자동으로 뜬다. 별도로 `게임 종료하기` 버튼 + 확인 모달이 있어 임의 종료도 가능하다.
2. **티르소스**: 판정은 `checkEndConditions()` 가 수행하지만 통지가 **토스트 + 기록 로그** 뿐이다. 토스트는 몇 초 뒤 사라져 놓치기 쉽고, 승자·사유가 남는 고정 화면이 없다. 사회자가 임의로 게임을 끝내는 버튼도 없다.
3. **재현 난이도**: 하 — 판정 로직이 이미 승자와 사유 문자열을 만들고 있으므로, 토스트 대신(또는 병행) 결과 카드를 띄우고 `게임 종료` 버튼을 하나 붙이면 된다.
4. **영향도**: 중 — 판정이 이미 동작하므로 오판 위험은 낮고, 놓침 방지·마무리 정리 수준의 개선이다.
- 참고: `tz-endgame.png`

### B5. 캐릭터 (i) 정보 모달 부재 — 스크립트 화면에서 전체 캐릭터 정보에 도달 불가
1. **teeroz**: 각 캐릭터 카드에 (i) 버튼이 있고, 누르면 이름/팀/영문명/능력/아티스트/인용/등장 스크립트/요약/진행 방법/예시(n)를 담은 모달이 뜬다. 백과사전으로 이동하지 않고 그 자리에서 전부 확인한다.
2. **티르소스**: (i) 버튼이 없다. `사회자 노트 N건` 아코디언은 재량·상호작용 팁만 담고 진행 방법·예시는 백과사전 탭으로 가야 한다.
3. **재현 난이도**: 하 — 백과사전 캐릭터 상세 렌더 함수가 이미 있으므로, 카드에 (i) 버튼을 달고 같은 내용을 모달로 띄우면 된다.
4. **영향도**: 중 — 게임 중 규칙 확인 시 탭 이동이 필요해 흐름이 끊긴다.
- 참고: `tz-char-info-modal.png` ↔ `th-char-note.png`

### B6. 참가자 입력 방식이 느리다 (프리셋 좌석 없음)

3. **재현 난이도**: 하 — 기본 7행 렌더 + 인원 스테퍼로 바꾸면 된다. 드래그는 별도(중).

3. **재현 난이도**: 하 — 후보 산출 로직은 이미 있고 버튼과 무작위 선택만 추가하면 된다.
4. **영향도**: 중 — 첫날 밤에 정보 캐릭터가 3~5종 몰려 있어 누적 조작량이 크다.

- 참고: `tz-m-play.png` ↔ `th-m-night.png`

### B11. 정렬 전환의 어포던스가 약함 (기능 자체는 정상)
> 정정: 초기에 `<select>` 부재만 보고 "미구현"으로 판단했으나, 실제로는 `sheetSort` 토글 버튼으로 동작한다. 브라우저에서 전환을 확인했다 — 기본 상태는 밤 순서순(세탁부·사서…), 토글 시 가나다순(군인·까마귀지기…).

1. **teeroz**: `가나다순` / `밤 순서순` 두 옵션이 드롭다운에 나란히 보여, 현재 정렬과 선택 가능한 대안이 동시에 드러난다.
2. **티르소스**: 버튼 하나가 `가나다순` ↔ `가나다순 ✓` 로 바뀐다. **현재 밤 순서순이라는 사실도, 그것이 선택지라는 사실도 화면에 없다.** 체크 표시가 꺼진 상태를 "가나다순으로 정렬됨"으로 오독하기 쉽다.
3. **재현 난이도**: 하 — 라벨을 현재 상태 기준(`밤 순서순 ▾`)으로 바꾸거나 2버튼 세그먼트로 교체.
4. **영향도**: 하 — 기능은 동작하므로 표기 명확성 문제에 그친다.
- 참고: `tz-script-sort.png` ↔ `th-script.png`

### B12. 캐릭터 확인 릴레이가 순서 고정 선형 15스텝
1. **teeroz**: 오버레이에 플레이어 명단이 뜨고 각자 **자기 이름을 탭**한다. 순서 무관, 늦게 온 사람도 재확인 가능, 확인 다이얼로그로 오탭 방지.
2. **티르소스**: `1/15 → 15/15` 선형 진행. 중간에 순서가 어긋나면 `이전`/`다음`으로 되짚어야 하고 특정 인물만 재확인하기 어렵다.
3. **재현 난이도**: 하 — 명단 그리드 + 확인 다이얼로그 + 카드 화면 3단으로 바꾸면 된다.
4. **영향도**: 중 — 게임당 1회지만 인원이 많으면 사고가 잦은 구간이다.
- 참고: `tz-reveal-1.png`, `tz-reveal-2-confirm.png`, `tz-reveal-3-1.png` ↔ `th-reveal.png`

### B13. `자리 섞기` / 배정 `전체 비우기` 없음
1. **teeroz**: 배정 단계에 `자리 섞기`(좌석 셔플)와 배정 후 `전체 비우기`.
2. **티르소스**: 좌석 셔플 없음. 참가자 단계의 `전체 초기화`는 참가자 자체를 지우므로 배정만 비우기 불가.
3. **재현 난이도**: 하.
4. **영향도**: 하~중 — 실물 좌석과 무관하게 배정을 다시 굴릴 때 편의 차이.

### B14. 헤더 부속 기능 부재 (공지 벨 / 언어 선택 / 로그인 / 공유)
1. **teeroz**: 공지 벨(최신 공지 API), 언어 드롭다운(정식판/번역판/en), 로그인, 스크립트 공유 버튼.
2. **티르소스**: 모두 없음. 대신 테마 토글이 있다.
3. **재현 난이도**: 공지·공유 하 / 언어 상(전 문자열 i18n) / 로그인 해당없음(백엔드 없음).
4. **영향도**: 하 — 단일 HTML 오프라인 도구라는 성격상 로그인·공지는 대체로 무의미. 공유는 URL 라우팅이 없어 성립하지 않는다.

### B15. 캐릭터 아트 토큰 대신 이모지
1. **teeroz**: `/icons/characters/{id}_{g|e}.webp` 원형 토큰 아트 + 위상 아이콘 webp.
2. **티르소스**: 이모지 1자. 단일 HTML 자족성을 위한 의도적 선택으로 보인다.
3. **재현 난이도**: 상 — 자체 제작 또는 라이선스 확보 필요(teeroz 자산 전용 불가). 인라인 SVG 세트 자작이 현실적.
4. **영향도**: 하 — 식별성은 다소 떨어지나 이름 병기로 보완되고 있다.

### B16. 홈 큐레이션 섹션 3종 부재 (이달의 커스텀 / 추천 / 틴시빌)
1. **teeroz**: `/api/scripts/featured?category=monthly_custom|recommended|teensyville` 로 각 1/4/3개 카드, 카드마다 `Storyteller n` `Player n` 복잡도.
2. **티르소스**: 공식 3종 + 빈 커스텀 슬롯만.
3. **재현 난이도**: 상 — 서버 큐레이션이므로 정적 복제하면 즉시 낡는다.
4. **영향도**: 하 — 사회자 진행에는 영향 없음. 복제 권장하지 않는다.

### B17. URL 라우팅·딥링크 없음
1. **teeroz**: 스크립트·위키·게임이 실 URL을 가져 북마크·뒤로가기·공유가 된다.
2. **티르소스**: 단일 HTML 내부 상태. 새로고침 시 홈으로 복귀.
3. **재현 난이도**: 중 — `history.pushState` + 해시 라우팅으로 부분 구현 가능.
4. **영향도**: 하~중 — 진행 중 새로고침 시 상태 유실 위험이 실사용 리스크다(다만 `☁ 저장`/JSON으로 완화).

### B18. 낮 타이머 없음
1. **teeroz**: 낮 진입과 동시에 경과 타이머가 헤더에서 돌아간다.
2. **티르소스**: 밤 타이머는 있으나 낮 타이머는 없다.
3. **재현 난이도**: 하 — 밤 타이머 컴포넌트 재사용.
4. **영향도**: 하~중 — 낮 시간 관리는 사회자 재량이지만 표준 진행에서 유용하다.

## C. 티르소스가 teeroz보다 나은 점

1. **라이트/다크 테마 전환** — teeroz는 다크 단일. 티르소스는 ◐ 토글 + `prefers-color-scheme` 자동 대응. 밝은 방 진행에 유리. (`th-default.png`)
2. **셋업 변형을 반영한 권장 구성** — teeroz는 인원별 정적 배분만 보여준다. 티르소스는 `권장 구성 (7인 · 남작 적용)` 처럼 셋업 변형 캐릭터를 반영하고, 현재 배정과 대조해 `구성 일치 / 불일치`를 실시간 판정한다. (`th-setup-assigned.png`)
3. **준비 완료 게이트** — 주정뱅이 위장 캐릭터 미지정 등 미완 항목이 있으면 진행을 막고 사유를 명시한다. teeroz에는 이런 검증이 없다. (`th-setup-step3.png`)
4. **플레이어 상태 토큰 6종 + 메모** — teeroz는 중독·취함·보호 3종. 티르소스는 주인(집사)·저주·광기를 더하고 플레이어별 메모 필드까지 제공한다. (`th-player-modal.png` ↔ `tz-player-modal.png`)
5. **2단계 투표 + 호명 순서** — teeroz는 단일 카운터 `−`/`+`. 티르소스는 1단계 거수(플레이어별 토글, 분자/분모/과반 실시간) → 2단계 찬반이며, 2단계에서 **피지명자 왼쪽부터 시계방향 호명 순서**를 명시하고 사망 투표 토큰을 반영한다. (`th-vote.png`, `th-vote-result.png`)
6. **정보 제안에 산출 근거 병기** — teeroz는 계산값만 보여준다. 티르소스는 `제안: 1 (이웃: 라 · 바 (등록 재량 반영 전))` 처럼 근거와 재량 여지를 함께 표시한다. (`th-night-wizard.png`)
7. **밤 위저드의 단계 세분화** — teeroz는 한 패널에서 슬롯을 채운다. 티르소스는 깨우기 → 선택 → 플레이어 대면 표시 → 재우기로 나눠 사회자 행동 단위와 1:1로 맞춘다.
8. **밤 타이머 + 템포 가이드** — `⏱ 밤 n 경과` 와 단계당 30~60초 권장 안내. teeroz에는 밤 타이머가 없다.
9. **사회자 체크리스트 탭** — 배정된 캐릭터를 기준으로 셋업 / 매일 밤 / 낮·투표 체크 항목을 자동 생성. teeroz에 없는 기능. (`th-check.png`)
10. **그리모어 전용 탭 (원탁/카드 2뷰) + 상태 만료 규칙 명시** — 중독은 다음 밤 시작 시, 보호·주인은 만료 페이즈에 자동 해제된다는 규칙을 화면에 고정 표기. (`th-grim.png`)
11. **게임 기록 + 전말 요약 + JSON 내보내기** — teeroz의 이벤트 로그보다 범위가 넓고, 게임 종료 후 복기용 서사 요약을 생성한다.
12. **백과사전 섹션이 더 두껍다** — teeroz의 등장 스크립트/요약/진행 방법/예시에 더해 **낮 능력·판정 팁**, **상호작용·주의**(징크스·등록 재량 포함)를 제공한다. (`th-wiki-char.png`)
13. **재량 응대 도우미** — 상황을 자연어로 입력하면 판정 체크리스트를 만들어 준다. teeroz에 없다.
14. **커스텀 캐릭터 빌더가 진행 로직에 통합** — 이름/유형/능력/밤 순서 삽입 위치를 지정하면 캐릭터 목록·밤 순서·체크리스트·투표 노티스에 자동 반영된다. teeroz의 `내 스크립트`는 기존 스크립트 관리(로그인 필요)에 가깝다. (`th-custom.png`)
15. **밤 순서 탭의 조건부 뱃지** — `오늘 밤 사망한 경우에만`, `악마 계승 시에만` 등 발동 조건을 항목에 직접 붙인다. teeroz는 설명 문장 안에 녹여 둔다. (`th-script-n2.png`)
16. **오프라인·무계정·단일 파일** — 로그인·서버·네트워크 없이 파일 하나로 완결. teeroz는 게임 저장·내 스크립트에 로그인이 필요하다.
17. **인쇄 전용 스타일** — `@media print` 로 네비게이션·버튼을 제거한 시트 출력 규칙을 자체 보유.
18. **승리 조건 판정이 더 촘촘하다** — teeroz는 종료를 감지해 사후 모달을 띄운다. 티르소스 `checkEndConditions()` 는 악마 사망 시 **탕녀 계승 가능 여부와 탕녀의 중독/오작동 상태까지 분기**해 "게임 계속"과 "선한 팀 승리"를 구분하고, 생존 2인 이하 + 악마 생존도 판정한다. 시장 3인 조건은 낮 패널에서 **사전 경고**(오작동이면 무효 표기)하고, 처형 없이 밤으로 넘어가려 하면 **확인 다이얼로그로 차단**한다. 사후 통지가 아니라 사전 개입이라는 점이 실무적으로 낫다.
